# 次回UI/UXブラッシュアップ: ローカルモデルへの接続

状態: 要件整理。設計・実装は未着手。対象バージョンは未定。

## 解決する問題

利用者が、モデルを動かすサーバーを別途用意する必要があるか、どこに何を設定すればよいか、接続できないときに何を確認すればよいかを判断できない。
設定を省略・自動入力しても、接続条件や現在の状態まで見えなくすると、準備と問題の切り分けを利用者に残してしまう。

次の大規模なUI/UX更新では、他の利用者が自分の環境でローカルモデルへ接続できる体験を整える。
特定の開発者の端末、起動スクリプト、モデルの保存パス、ポート番号を利用の前提にしない。

## 要件

- **汎用的な入出力と接続設定**: 既存のOpenAI互換API接続を土台に、接続先URL、モデルID、認証、対応するAPI形式を確認・変更できる。モデル固有の要求・応答形式が必要な場合は専用の変換処理として扱い、汎用モデルとの違いや適用条件を明示する。
- **確認できる接続状態**: 接続を試す操作と結果を用意する。設定が保存されたこと、サーバーへ到達できたこと、選択したモデルと形式で翻訳できたことを混同しない。
- **失敗後の操作が分かる案内**: サーバーを別途起動する必要があるかを説明する。接続先に到達できない、認証に失敗した、モデルIDやAPI形式が合わないなど、判別できる範囲で原因と次の確認・再試行の操作を示す。原因を判別できない場合は、その旨を表示する。
- **設定が見えるプリセット**: 「PLaMo（このMac）」等のプリセットを設ける場合は入力補助として扱う。何が設定されたかを確認・変更でき、プリセットを使わずに対応サーバーへ接続する方法も残す。

## 受け入れ条件

- [ ] 新規のFirefoxプロファイルから、文書化された対応形式のサーバーへ、接続先・モデル・必要な認証を設定して翻訳できる。開発者の端末固有の値やコード変更を必要としない。
- [ ] PLaMoの翻訳専用形式と汎用モデルの形式について、必要な設定と利用可能な機能の違いが画面で分かる。
- [ ] 接続を確認でき、疎通だけ成功して翻訳要求が失敗する状態を「翻訳可能」と表示しない。
- [ ] サーバー停止、認証エラー、モデル指定の誤り、非対応のAPI形式について、取得できる応答に応じた案内と次の操作が表示される。
- [ ] プリセットを設ける場合、適用された設定を確認・編集でき、別の対応サーバーやモデルへ変更できる。
- [ ] ブラウザ・OSの再起動後も保存済み設定を利用できる。サーバーが起動していない場合は、現在の接続状態と必要な起動手順を確認できる。

## 設計時に決めること

- 対応API形式とモデルの範囲、モデル固有の変換処理の境界。
- 接続確認の通信内容、状態の更新タイミング、エラー表示の粒度。
- プリセットの有無と内容、モデル一覧の取得に対応しないサーバーでの設定方法。

サーバーの自動インストール・起動・停止を拡張機能から行うことは、この要件では決めていない。
本書のチェック項目は、実装時の受け入れ条件であり、現在の実装が満たしていることを示さない。
